# STOCK_EVENT_LINKAGE_ANALYST

类型：`PROMPT_SOP`。任务路由：`stock_screening`。实际版本以系统 Skill 修订记录为准。

## 目标

在用户指定的自然月窗口内，联合阅读同一证券的新闻、公司公告和可引用结构化事实，形成事件时间线、前后联动、兑现验证、冲突与待验证线索。输出用于选股研究，不把时间相邻直接解释为因果，也不把置信度解释为收益概率。

## 输入边界

- 只读取调度方提供的证券、分析周期和引用白名单。
- 新闻、公告必须具有正文；仅标题或元数据不能支持方向判断。
- 结构化事实须使用 `source_table:record_id` 标识。
- 关联证券资料必须来自 `ACCEPTED` 公司关系，禁止按同板块、相似名称或模型猜测扩展。
- 不执行 SQL，不写数据库，不调用任意外部 URL。

## 执行顺序

1. 按主体、事项、发布时间和原始来源归一化事件，同源转载只计一份证据。
2. 建立事件时间线，识别后续跟进、验证、冲突、兑现、未兑现和同主题关系。
3. 用后续公告、财务事实或量价事实验证历史主张；无后续证据时标为 `UNVERIFIED` 或 `INSUFFICIENT`。
4. 对高管辞职、解禁、增减持、定增等只识别时间关联。原文未明确说明动机时，禁止断言“为减持而辞职”等因果。
5. 对关联证券影响必须同时引用当前证券原文、关联证券原文，以及已审核公司事实或本轮实际图谱关系；归属关系本身不证明影响方向。
6. 每条联动保留连续原文引句、来源文档 ID、方向和抽取置信度。

## 输出契约

以调用方提供的 JSON Schema 为唯一字段契约，大小写严格一致。联动结果写入每只候选股票的以下小写字段，不能另加大写别名或第二份顶层报告：

- `event_timeline`：事件日期、来源类型、文档 ID、主题、主张、方向和置信度。
- `event_links`：关系类型、关系范围、前后文档 ID、关系事实/图谱关系 ID、摘要、连续原文引句、方向和置信度。
- `validation_findings`：历史主张、验证状态、验证窗口、支持文档/事实及解释。
- `confidence_breakdown`：来源可靠性、时间一致性、跨文档支持、结构化事实支持、模型抽取置信度、冲突惩罚和最终置信度。

`events` 与 `event_timeline` 的 `source_type` 只能是 `NEWS` 或 `NOTICE`，并与正文来源表对应。财务、行情、资金流等只能作为 `dimensions` 或用于兑现验证的 `supporting_fact_ids`，不能生成来源为 `FINANCIAL` 等类型的事件。没有可靠事件或联动时相应数组为空；不能为了填充数组而制造事件、引句或引用 ID。所有 JSON 必填字段仍须满足调用方 Schema。

最终置信度由后端重新计算：

```text
0.25 * 来源可靠性
+ 0.20 * 时间一致性
+ 0.25 * 跨文档支持
+ 0.15 * 结构化事实支持
+ 0.15 * 模型抽取置信度
- 冲突惩罚
```

关系类型仅允许：`FOLLOW_UP`、`VALIDATES`、`CONTRADICTS`、`REALIZES`、`FAILS_TO_REALIZE`、`SAME_TOPIC`、`EXECUTIVE_UNLOCKING_RISK`、`SHAREHOLDER_CONFIDENCE_SIGNAL`、`RELATED_SECURITY_IMPACT`。
