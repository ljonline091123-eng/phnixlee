# 选股八维评价体系实施与验收说明

## 1. 实施范围

本次为增量扩展，不删除或重建已有数据。保留原七维资料卡、知识库、图谱、GraphRAG、人工复选、预测账本和十日跟踪，在其上新增版本化八维评分、主营与竞争壁垒专项、产业链事件传导专项及 T+3/T+5/T+7 评估。

核心实现：

- 数据模型：评价维度、权重方案、方案明细、候选维度结果、周期评估。
- 评分服务：财务、估值、行业、价格、资金、事件、治理和产业链八维计算。
- 管理接口：方案查询、复制、编辑、发布、停用、回滚、候选补算和评估汇总。
- 管理界面：`#/ai/scoring`。
- 分析界面：可信综合分、八维雷达图、覆盖率、证据置信度、指标和警告下钻。

七个新增评分 Skill 均使用 `SELECTION_SCORING_V1` 受控契约：输入限定为候选身份、评分时点、方案和有界证据；输出固定为维度状态、方向、分数、覆盖率、证据置信度、指标、证据和警告；权限为只读，幂等策略为 `REQUIRED`，错误策略为返回证据不足而非伪造替代分数。事件维度复用已有 `STOCK_EVENT_LINKAGE_ANALYST`。

## 2. 数据与计算边界

| 内容 | 处理原则 |
|---|---|
| 财务与估值 | 只使用可识别指标编码、报告期和数值，不补造缺失字段 |
| 行业联动 | 使用标准行业及同市场同行样本，主题标签不替代行业 |
| 量价 | 使用同证券、同周期的本地日线，计算收益、波动和回撤 |
| 资金 | 只读取明确资金字段，禁止任意取首个数值 |
| 新闻公告 | 使用通过文档 ID 和原文引句校验的 LLM 语义结果 |
| 治理与关系 | 资料归属边和候选关系不视为已验证业务事实 |
| 缺失数据 | 标记 `INSUFFICIENT`，不计零分，不伪造完成 |
| 主营与竞争壁垒 | 主营构成数值必须回指 `BUSINESS_COMPOSITION`；技术领先、国产替代、客户验证及市场份额必须有原文或专项事实 |
| 产业链事件传导 | `VERIFIED` 必须引用已审核关系事实和关联证券重大事件；候选/未验证关系仅展示线索，不计方向分 |

## 3. 数据库迁移与回滚

前向迁移：`backend/migrations/009_selection_scoring.sql`。

回滚脚本：`backend/migrations/009_selection_scoring.rollback.sql`。

回滚只删除本次新增的五张评分表，不修改已有选股批次、候选、证据、决策、跟踪和预测账本。生产回滚前应先创建一致性数据库备份。

## 4. 验收标准

1. 初始化后存在八个中文评价维度、一个已发布短周期方案和一个综合研究草稿。
2. 新建选股可选择已发布方案，批次保存不可变方案快照。
3. 每个新候选生成八条维度结果；缺失项为 `INSUFFICIENT` 且分数为空。
4. 雷达图只表达原始维度分；缺失轴留空；可信综合分显示覆盖和置信度。
5. 草稿权重不等于 100% 时不能保存或发布；已发布方案不能直接编辑。
6. 旧候选可显式补算，原证据和原模型结论保持不变。
7. 跟踪刷新后生成 T+3、T+5、T+7 的真实交易日结果，缺行情保持 `PENDING_DATA`。
8. 管理页在桌面和窄屏均无文字遮挡、不可控横向页面滚动或失效按钮。
9. 选股详情单列“主营业务与竞争壁垒”和“产业链关联公司重大事件影响”；历史 V4 结果明确提示未执行 V5 专项分析。
10. 公司资料补齐同时核验 `profile` 与 `business_composition`，来源为空时保持缺口；不得用模型常识补市场份额或供应链关系。

## 5. 已知边界

- 行业基准指数收益尚未接入，当前行业维度使用同行中位收益和上涨广度；周期评估中的基准/超额字段保留为待接入状态。
- 历史候选的补算使用其冻结证据和当前已发布评分规则，不会制造当时不存在的原文，但确定性评分算法版本属于本次补算版本。
- 权重优劣需要至少 30 个独立决策窗口和样本外验证后再判断，当前默认权重是首版可解释基线。

## 6. 三轮验收结果

1. 规则与接口：评分、版本生命周期、旧候选补算、失败任务重试兼容、候选关系隔离及 T+3/T+5/T+7 交易日计算通过自动化测试。
2. 迁移与前端：前向/回滚迁移、生产构建、权重合计门禁、中文复制对话框、桌面与 390px 移动端布局通过。
3. 真实数据：20 个历史候选生成 160 条八维结果和 60 条周期评估；证据不足维度保持空分，周期行情尚未到达的 60 条记录保持 `PENDING_DATA`，未伪造未来表现。
