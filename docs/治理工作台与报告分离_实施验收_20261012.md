# 治理工作台与报告分离：实施与验收

日期：2026-10-12。

本轮完成治理执行、交互待办与只读报告的界面分离。治理主窗口展示节点、进度和当前处理对象；阶段、股票、文档与证据明细按需打开。继续治理使用现有后端续作接口创建并启动独立任务，原报告保留。

## 2. 交互设计与实现

| 用户要求 | 实现行为 |
| --- | --- |
| 执行窗口与报告分离 | “运营治理”分别提供“治理工作台”和“治理报告”。报告页只查询，不启动、续作、审核或写入数据 |
| 主窗口展示总体节点和进度 | 治理过程主窗口显示任务状态、进度、当前文档、阶段节点及简要错误；详细结果不全部铺在主窗口 |
| 分项治理弹窗 | 点击节点打开节点明细；新闻公告结构化进入独立过程窗口，再从文档待办打开单篇交互窗口 |
| 继续治理可以看到执行过程 | 先显示缺口和定向续作计划，确认后调用续作接口，切换到新任务，自动显示执行过程；保留旧任务和报告 |
| 网络或执行失败反馈 | 操作中禁用重复点击、就地显示错误；续作请求重试复用幂等键，进度读取失败自动重试 |
| 减少单屏信息量 | 任务列表、报告列表、股票明细与文档待办分页；报告概要、阶段、质量、历史、Skill与审计分窗口展示 |
| 多层窗口可用 | 逐层 Esc 关闭、Tab 焦点约束、关闭后恢复焦点和滚动状态；兼容窄屏 |
| 当前任务与专项治理关联 | 专项链接携带任务 ID 与股票范围；刷新及同页面 hash 参数变更能够恢复该任务与文档待办，不混入旧勾选 |

### 治理工作台

入口：`#/operations/workbench`，指定任务：`#/operations/workbench?job=<任务ID>`。

列表支持搜索、状态筛选及每页20条。执行中的主窗口约每2.5秒读取一次最新任务，列表约每5秒刷新；轮询避免请求重叠，切换任务时取消旧轮询。

“立即执行”调用后端启动接口并展示反馈。失败任务使用现有重试接口；已结束但部分完成的任务使用“继续治理 → 确认定向续作计划 → 确认并开始续作”。续作创建新任务，不覆盖原报告。

节点明细随任务进度更新。终态中未形成成果的节点显示“本轮未执行”，避免任务已经结束却仍显示“等待执行”。Skill优化在节点明细内完成草稿、测试、审核或驳回；只有测试通过的草稿可批准。

### 新闻公告知识结构化

入口：`#/operations/documents`；从工作台结构化节点进入时携带当前任务。

过程主窗口显示后台进度、当前文档与交互节点。点击“查看处理文档与交互待办”打开分页明细，再逐篇打开交互治理窗口：核对类型与Skill、确认方案、核对结构化知识点与证据、反馈不符合项、再次分析、确认发布或选择不治理。

后台处理结束不会自动替用户发布。当前任务的文档范围来自任务目标与执行结果；历史页面的旧勾选不进入该任务的待办。原有按来源表及记录 ID 直接打开文档的链接保留。

### 治理报告

入口：`#/operations/records`，指定报告：`#/operations/records?job=<任务ID>`。

主窗口展示报告概况、数量统计、阶段状态和明细入口。阶段、股票、质量、治理历程、Skill执行、审计及数据证据分别按需查看；阶段数据预览可继续打开证据明细。

未完成项通过携带任务 ID 的链接进入工作台处理。报告窗口自身无写操作，避免查看结果时误启动治理。

## 5. 用户逐项验证

1. 刷新系统，进入“运营治理 → 治理工作台”，查找部分完成的任务并点击“进入治理窗口”。核对主窗口仅显示概要、节点、当前对象和进度。
2. 点击“继续治理”，核对计划中的股票范围、未完成项及处理规则。点击“确认并开始续作”，观察窗口切换到新的任务 ID，状态从等待领取进入执行，进度和当前文档自动刷新。旧任务报告仍可查询。
3. 打开任一节点明细，查看分项结果；进入“新闻公告知识结构化”节点的专项窗口，核对任务 ID 与待办文档范围一致。
4. 从专项过程主窗口打开文档待办，翻页并逐篇进入交互治理。按方案确认、知识点核对、反馈不符合项、再次分析、发布或不治理的顺序操作。重点确认项未完成时不能直接发布。
5. 进入“治理报告”，查看刚才任务的概要。依次打开阶段、股票、质量、历史、Skill、审计与证据明细；确认报告没有“立即执行”“继续治理”等写入按钮。
6. 在多层窗口按 Esc，确认每次只关闭最上层；在窄屏核对文字换行和按钮可用。关闭窗口后，后台任务仍由执行器处理。
7. 核对报告中的成功、失败、部分完成与待确认数量，避免把进度100%当成所有知识点通过质量门禁。

## 6. 兼容与回滚

原数据源、接口、股票公司主数据、湖仓对象、模型、Agent、Skill、知识库、历史图谱与任务报告均保留。既有 `#/operations/records` 查询入口及文档来源链接继续可用。新增工作台使用增量路由，不替换其他业务模块。

本轮无数据库结构变更，不需要迁移或降级脚本。若需撤回界面，可先从备份提交建立独立 Git worktree，对比本轮前端和验收脚本的增量，逐项回退这些文件；当前工作区还包含其他轮次成果，不能直接重置到备份或覆盖全部改动。数据库备份用于恢复演练与灾难恢复，不应直接覆盖之后产生的有效治理成果。

## 7. 当前边界

- 既有“继续治理”后端计划每轮结构化20篇，计划中明确提示，剩余保持 `PARTIAL`。本轮未修改该策略；专项按股票批量可选择全部未完成文档，分批执行。
- Skill草稿的测试属于离线规则与契约检查，测试通过不代表远程采集、OCR或真实模型抽取全部成功。
- 人工确认和发布表示结构化结果经过用户确认，外部事实的核验状态仍单独保留。
- 进度100%表示本轮处理结束，质量结果可能是部分完成或失败；没有降低质量门禁来伪造成功。
- 前序真实任务 #539 的四篇文档仍存在数字、单位或原文引文校验失败，历史原因保留。本轮改善操作与报告可读性，不将这些历史数据标记为质量通过。
- 本轮完成本地开发和上述验收，没有进行生产部署。真实数据源及模型质量需在同一交互流程中按文档继续核验。
