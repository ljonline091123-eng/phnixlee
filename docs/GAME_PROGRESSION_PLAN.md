# FiveLines 游戏优化与长期成长方案

## 1. 目标与范围

本方案面向 FiveLines 的长期体验优化与成长系统建设。

- Android 作为玩法和界面的基准版本，iOS 的玩法与成长数据向 Android 对齐。
- H5 版本不在本方案修改范围内。
- 每日挑战、奖牌、能力卡等内容采用集中、数据驱动的定义，便于持续增加和调整。
- 每日挑战及未来的联网公平对战不受装备卡影响。
- 联网功能必须由真实服务端支持；没有服务端时，只实现本地档案和客户端接口准备，不将本地功能标示为已联网。

## 2. 界面可读性

### 目标

改善顶部信息、分数、说明文字、按钮、菜单、教程和弹窗的可读性，避免因屏幕尺寸或密度差异造成文字过小。

### 实施要求

- 检查字号、控件尺寸与布局是否使用了不适合当前屏幕密度的固定像素值。
- 主要状态信息、游戏说明和按钮文字优先提升字号及对比度。
- 触控区域要足够大，避免只放大文字却仍难以操作。
- 在不同尺寸与密度的模拟器或设备上检查布局，避免文字重叠、裁切或棋盘区域被挤压。
- 重要信息不应只依赖颜色表达；颜色需配合文字、图标或形状。

### 验收标准

- 常见手机模拟器上顶部文字、分数和关键按钮无需放大画面即可辨认。
- 菜单、教程和挑战说明没有裁切或遮挡。
- 棋盘与控制区仍可正常操作。

## 3. 启动实操引导

### 目标

游戏启动默认进入可操作的新手引导关卡。引导应让玩家亲自完成操作，而不是只阅读弹窗说明。

### 引导步骤

1. **认识棋盘与棋子**：指出棋子、可选位置和当前任务。
2. **移动棋子**：引导玩家选择棋子，再选择目标空格；操作后说明棋子如何移动。
3. **连线消除**：使用预设局面引导玩家完成一条有效连线，并展示消除反馈和得分变化。
4. **使用白棋**：展示白棋如何补足颜色或完成连线，并由玩家实际操作一次。
5. **使用炸药**：展示炸药的作用范围和使用方式，并让玩家完成一次有效爆破。
6. **结束与继续游戏**：总结基础操作，允许玩家进入正常游戏。

### 状态与入口

- 首次启动或尚未完成教程时，默认进入引导。
- 引导完成后持久化记录完成状态，之后启动直接进入正常游戏。
- 主菜单保留“重新学习”入口，可主动再次进入教程。
- 教程流程应避免因误操作卡住；提供明确提示、重试或继续操作方式。
- 教程使用可控局面，不能依赖随机棋子恰好生成关键教学场景。

### 验收标准

- 新玩家能在引导中实际完成移动、消除、白棋和炸药操作。
- 完成教程后重启游戏不会再次自动进入教程。
- 从菜单重新进入教程仍能完整走完流程。

## 4. 每日残局：首期 30 关

### 设计目标

每日挑战必须呈现可辨识的预设图案或残局局面，而不能只是日期变化或随机棋子变化。每关应有明确目标，并能通过游戏规则判定是否完成。

### 规则建议

- 首期制作 30 个预设残局，按日期每日轮换一道；每天可重复游玩。
- 每关包含主题、棋盘布局、特殊棋子位置、通关目标、步数或其他限制、提示和奖励。
- 玩家首次通关获得固定奖励；重复通关可继续练习，但不重复领取首通奖励。
- 所有残局上线前需验证可解。首期可人工试玩验证并记录测试解法；后续可加入自动求解检查。
- 残局的基础规则对所有玩家一致，不受装备卡效果影响。
- 图案主题用于表达关卡视觉和故事主题；通关判定仍以可验证的消除目标、目标颜色、指定区域、连线次数或剩余步数为准。

- 通关条件与步数限制
- 提示、撤销等功能是否允许
- 首通奖励及领取状态
- 测试解法或人工验证记录
- 发布状态、创建日期和最近更新时间

## 5. 12 阶等级奖牌

### 设计原则

- 等级由累计成长分决定，不因单局失败或连续登录中断而下降。
- 每一级由名称、颜色和奖牌图案共同识别，不能只靠颜色区分。
- 页面展示当前等级、当前成长分、距离下一等级所需分数及成长分来源。
- 晋级阈值应通过实际游戏节奏校准，避免升级过慢或过快。

### 成长分来源建议

## 6. 54 张能力卡

### 卡牌规则

- 共 54 张，分成 7 组：前 6 组各 8 张，第 7 组 6 张。
- 每张卡记录名称、解锁条件、能力说明、获得时间、稀有度和解锁状态。
- 卡牌分为收藏卡和装备卡：
  - **收藏卡**记录技巧、挑战或里程碑，不改变玩法。
  - **装备卡**只在普通休闲模式提供有限辅助；每日残局和未来联网公平对战中不生效。
- 普通模式每局最多装备 3 张，避免叠加效果破坏平衡。
- “能力”可以是成就记录、外观奖励或有限的休闲模式辅助，不应把所有卡都设计为战力加成。

- 卡牌提供的辅助应以可控、有限、易理解为原则。

## 7. 玩家档案与联网模式

### 本地玩家档案

首期可建立本地玩家身份档案，包含：

- 用户名及本地玩家 ID
- 当前等级与成长分
- 个人最高分
- 已获得的奖牌与能力卡
- 每日挑战记录及完成进度

用户名修改应与玩家 ID 分开保存；修改显示名称不应导致进度丢失。

### 联网能力边界

联网账号、数据同步、匹配和对战需要服务端支持。客户端不可将本地数据冒充在线数据。

后续联网版本至少需要服务端实现：

- 用户注册、身份认证与找回机制
- 玩家档案和进度安全同步
- 每日挑战内容与完成记录校验
- 实时或回合制匹配与对局同步
- 异常退出、断线重连和对局结果确认
- 服务端防作弊及数据校验

在服务端部署前，客户端可以保留清晰的联网接口边界，但应明确标示“尚未开放联网”，不提供看似可用但实际无法完成的在线匹配。

## 8. 内容维护入口

主菜单增加“收藏与挑战”入口，包含三个页面：

### 每日挑战

- 展示今日残局、目标、限制、奖励和完成状态。
- 展示历史完成记录及首期 30 关图鉴。
- 显示内容版本与最近更新信息。

### 奖牌与卡册

- 展示当前等级、成长分及下一阶进度。
- 按 7 组浏览 54 张卡。
- 未解锁卡片显示解锁条件；已解锁卡片显示获得时间。
- 展示当前已装备卡片及其适用模式。

### 内容维护

首期作为游戏内的内容图鉴与版本说明页面，包括：

- 当前挑战内容版本及关卡数量
- 奖牌与能力卡数量
- 最近新增或调整的内容
- 内容更新时间和版本记录

首期不提供任意编辑棋盘的游戏内编辑器。关卡和卡牌数据集中定义，供后续开发或运营扩充；若将来需要在线运营编辑，再建设带权限控制的管理后台和服务端接口。

## 9. 数据与存档要求

- 挑战、奖牌和卡片使用稳定 ID，不以界面名称作为唯一识别依据。
- 玩家进度按 ID 保存，调整文案或图案时不丢失已有解锁记录。
- 已领取的一次性奖励应持久化，避免重启或重复挑战造成重复发放。
- 新增内容应兼容旧存档；存档升级需有版本号和安全迁移逻辑。
- 如发生数据格式升级，不通过清空工作区或重建全部数据解决。
