# 新闻公告全文语义治理专项

## 目标

将新闻、公告从“标题/关键词摘要”升级为“LLM 全文语义理解 + 严格契约抽取 + Agent/Skill 证据治理”。输出仍是待审核候选，不把媒体观点或模型推断冒充已验证事实。

## 处理链路

1. 从现有 `stock_news`、`stock_notice` 读取保存的正文和来源信息；正文缺失时沿用既有受控补取机制。
2. `NEWS_NOTICE_EVENT_GOVERNOR` 第一次调用真实模型，阅读全文并形成概览、主题、时间线、因果和不确定性。
3. 第二次调用真实模型，按 `SEMANTIC_V2` 契约抽取主体、事件、数字、分维度影响和关系。
4. 程序逐项核对原文逐字引文、数字、单位、完整日期和关系端点；未通过校验的结果不入事实库。
5. 主体只解析到已有且唯一的实体身份，其他主体保存为“文档提及·待消歧”。
6. 事件和关系分别写入现有 `FoundationFact`，证据写入 `FoundationEvidence`，状态统一为 `PENDING / CANDIDATE`。
7. 保存模型调用、模型版本、Skill 版本、执行批次、正文哈希和证据编号；相同正文、Skill 和契约版本保持幂等。
8. 新版本成功后只追加旧候选的驳回审核记录，不删除旧事实、证据或治理历史。
9. 人工可对事件、指标、影响、主体和关系逐字段核验；批注、确认、驳回、修正及重分析均写入追加式审核轨迹。
10. 人工修改创建新的候选版本与候选事实，旧候选保留并退出当前版本；同一正文最多执行两轮人工反馈定向重分析。

## 事实边界

- `REPORTED_FACT`：新闻转述的披露或已发生事项，仍需原始来源交叉核验。
- `AUTHOR_OPINION`：记者、媒体或专家观点，必须保存明确归属。
- `MODEL_INFERENCE`：模型推断，不能升级成披露事实。
- 利润、现金流、融资、治理、监管、经营和股价分别判断；没有股价证据时不推断确定涨跌。
- 法院程序性驳回不等于税务实体违法认定；“以套利为目的”只能保留为作者观点。

## 专项入口与接口

- 页面：`运营治理 → 新闻公告语义治理`
- 路由：`#/operations/documents`
- 文档列表：`GET /api/v1/document-governance/documents`
- 文档成果与历史：`GET /api/v1/document-governance/documents/{source_table}/{record_id}`
- 发起专项治理：`POST /api/v1/document-governance/analyze`
- 查询审核历程：`GET /api/v1/document-governance/documents/{source_table}/{record_id}/reviews`
- 提交人工审核：`POST /api/v1/document-governance/documents/{source_table}/{record_id}/reviews`
- 字段级版本对比：`GET /api/v1/document-governance/documents/{source_table}/{record_id}/compare`

专项任务通过现有 `AI_AGENT_SKILL_GOVERNANCE` 队列执行，不在 HTTP 请求中直接运行模型。页面提供全文理解、事件与数字、主体与关键联系、时间线、原文证据、人工审核与版本对比、执行版本七类成果。

## 人机审核闭环

- 审核员在原文高亮与结构化值双栏中逐字段确认、修改、驳回或批注，并说明核验依据。
- 人工“确认结构”只形成 `HUMAN_CONFIRMED` 审核状态，不把 `FoundationFact` 从 `PENDING / CANDIDATE` 自动升级为权威事实。
- 人工修改执行原文引文、数字单位、主体名称和枚举值门禁；通过后创建 `CORRECTED_CANDIDATE` 新版本，旧候选追加驳回记录。
- 对整篇文档提出定向反馈会进入现有异步治理队列；模型同时读取上一版结构与审核意见，并保留未被质疑的有证据字段。
- 同一正文最多两轮反馈重分析，避免无限模型循环；到达上限后转人工处理或等待原文更新。
- 版本对比按字段显示章节、事件、主体、关系、指标和影响的新增、删除、修改，并单列事实 ID 血缘变化。
