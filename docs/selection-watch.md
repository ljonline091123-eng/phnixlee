# 选股盯盘与知识治理验收

## 页面入口

模型实验室的“调试与日志”支持模型实例下拉选择；“自动路由”交由任务路由选择模型，结果和调用日志显示实际执行实例。指定模型前应先完成供应商连通性测试。

知识库下仍可建立多张独立图谱。治理报告区分来源数据、各股票的维度覆盖和待补充信息。关系中的短文本仅为预览，打开原文可读取已入库的完整资料。来源本身只有摘要时，系统不会补造全文。

“补充外部证据”用于录入政策、原材料、上下游、股东变动、合同等资料，需选择股票并填写来源、链接、发布时间和原文。数据进入 `stock_context_event`，加入知识库和图谱来源后再执行治理。同一来源的重复文本会去重；相关主体提及不自动等同于已确认的因果关系。

## 选股与人工复选

1. 打开“选股盯盘 → 选股与复选 → 新建选股”。
2. 选择市场、知识库、独立图谱和分析模型，设置量价规则及候选数量（最多 50 只）。可指定一组股票代码，或从本地已有行情筛选。
3. 硬规则扫描所选市场的本地结构化行情；模型只接收筛选后的候选和有限证据，按来源保留财报、新闻、量价和事件资料，分批调用以限制上下文。规则预选与模型分析结果分开标记，缺数据或模型失败不会伪装为完整研判。
4. 在“证据与复选”核验资料、预测目标价和置信度，填写复选理由，然后确认入选或排除。人工确认后才创建预测跟踪；查看历史批次可追溯当时判断。

“历史分析”按市场和股票聚合全部选股批次，支持名称、代码检索和分页。选择股票后可切换每次分析，核对当时的数据截止日、模型、分析契约、结论和原文证据。历史记录只读；新建批次或主动重试不会通过历史页面改写旧版 V4/V5 结果。

新分析使用 `FUNDAMENTAL_THESIS_V7`，默认分析最近 12 个自然月。模型先形成一条整体逻辑，而不是先把八个维度分别写满：

```text
主营赛道未来趋势
→ 公司竞争位置与收入承接能力
→ 收入利润质量与可持续性
→ 第二曲线兑现概率
→ 公司行为、治理与股东回报
→ 已审核产业链传导
→ 估值与机构预期
→ 一年量价、成交量、回撤及事件后表现
→ 支持证据、反证、失效条件与综合结论
```

核心行业只能有一个；核心主题必须引用主营构成事实或可阅读全文，相关度低于 50% 不得升级为核心主题。最多形成三条投资假设，每条证据都记录支持/反证立场、公司特定影响和逐字原文引句，禁止根据标题给文章定性。机构预测表示市场预期，不当作已实现业绩。候选弹窗分为“结论分析、数据事实与问题、原文事实与血缘、执行审计”；错误和覆盖状态不再占用结论页。

产业链与外部韧性允许形成“证据不足”的中文结论，但只有已审核的客户、供应商或合作关系事实才能形成具体公司间的方向和评分。主营赛道、客户生态或新闻提及可用于解释外部依赖风险，不能替代关系事实。分析后的约 800 字 LLM 文字评价是独立的展示增强项；它调用失败时保留失败记录并允许单独重试，不会把已通过证据核验的核心结论和八维评分降级为分析失败。

候选证据使用 `GRAPH_RAG_CONTEXT_V6`。文档、关系、公司审核事实、结构化观测、切片、湖仓版本和血缘均按选股运行的 `as_of` 截断。长周期资料按记录分段阅读，最终研判只接收可核验摘要、原文引句和证据白名单；完整原文始终保留在证据快照中。切片区同时显示“已有有效切片”和“实际载入本次上下文”两种覆盖率。

## 跟踪与复盘

“跟踪与复盘”显示基准价、目标价、有效交易日进度、累计收益和最大回撤。有效日来源于同一口径的日行情记录，不能用自然日、未来行情或同一天的重复记录凑满十天。数据不足时保持等待状态。

以人工确认的市场当地日期为起点，只纳入之后已收盘的有效日线。港股与内地市场使用不同的日线完成时间，并预留行情落库缓冲；半日市采用保守的晚间确认，不提前使用盘中数据。依据：[港交所交易时段](https://www.hkex.com.hk/Services/Trading-hours-and-Severe-Weather-Arrangements/Trading-Hours/Securities-Market?sc_lang=en)、[上交所交易时段](https://english.sse.com.cn/start/trading/schedule/)。

收益和回撤当前采用不复权收盘价，表示价格变化，不含手续费、分红及税费；目标触及同样按收盘价判断。预测基准保留人工确认页面展示的历史快照，不将其伪称为实际成交。复盘完成后冻结当时前十个有效日的结果。

点击“更新跟踪与复盘”可手动更新。自动更新使用既有数据库任务队列，需要后台进程运行：

```powershell
cd backend
python -m app.jobs.scheduler
```

另一个终端启动 Worker：

```powershell
cd backend
python -m app.jobs.worker
```

真实新建预测需要等待未来至少 10 个有效交易日，系统测试中的模拟时间不能作为真实预测业绩。复盘指标用于检验当时假设和数据覆盖，不会自动交易，也不会覆盖原有预测。

复盘出现方向偏离、目标未达或触发止损后，可在复盘记录点击“运行 Skill 回归”。系统只用决策当时可见的证据执行历史盲测，未来收益只参与评分；真实元评审模型可生成待审核草案，Mock 或模型不可用时不会伪造草案。任何修复草案都必须在模型实验室人工审核，不会自动修改现行 Skill。

## 本次数据覆盖核查

2026-09-18 已备份数据库并用已有本地数据重建未锁定图谱。重建结果为 83,429 篇文档、107,207 个实体和 176,332 条关系，合并重复新闻/公告 1,562 条。数量增长本身不代表信息完整。

当前基础资料共有 19,165 只证券；量价覆盖 17 只，财务指标覆盖 13 只，股东资料覆盖 12 只。新增的政策、原材料、上下游等外部事件表尚为空。因此图谱保留“待治理”状态，并在覆盖报告中展示逐股票缺口。外部事件可通过页面或 API 导入；目前没有新增一个能自动补齐全市场政策、合同及产业链信息的外部供应商。

模型连通性依赖供应商 Key、余额与当前实例配置。自动化测试使用模拟模型验证调用契约、分批、失败降级和预测落库，不代表供应商服务始终可用。

## API 与存储

| 功能 | API |
| --- | --- |
| 新建 / 列出选股批次 | `POST /api/v1/selection/runs`、`GET /api/v1/selection/runs` |
| 批次与候选详情 | `GET /api/v1/selection/runs/{id}` |
| 按股票查询历史分析 | `GET /api/v1/selection/history`、`GET /api/v1/selection/history/{market}/{symbol}` |
| 读取指定历史候选 | `GET /api/v1/selection/candidates/{candidate_id}` |
| 人工确认 / 排除 | `POST /api/v1/selection/candidates/{id}/review` |
| 跟踪清单 / 详情 | `GET /api/v1/selection/tracking`、`GET /api/v1/selection/tracking/{id}` |
| 手动更新 | `POST /api/v1/selection/refresh` |
| 决策审计 / 复盘版本 | `GET /api/v1/selection/candidates/{id}/audit`、`GET /api/v1/selection/tracking/{id}/retrospectives` |
| GraphRAG 时点上下文 | `GET /api/v1/selection/context/{market}/{symbol}` |
| 复盘回归与修复草案 | `POST /api/v1/skill-evaluations/retrospectives/{id}/repair-flow` |
| 补充 / 查询外部证据 | `POST /api/v1/resources/context-events`、`GET /api/v1/resources/context-events` |
| 图谱证据原文 | `GET /api/v1/resources/knowledge-graphs/{graph_id}/documents/{document_id}` |

相关表为 `selection_run`、`selection_candidate`、`selection_tracking`、`selection_snapshot`、`selection_decision_snapshot`、`selection_retrospective`、`skill_evaluation_case`、`skill_evaluation_run`、`skill_evaluation_result` 和 `stock_context_event`。各表及字段释义同步到 `database_table_comment`。原有预测账本继续用于保存预测及复盘关联。
