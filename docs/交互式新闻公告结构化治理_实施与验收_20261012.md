# 交互式新闻公告结构化治理：实施与验收

本轮将新闻公告治理改为“LLM阅读全文 → 用户确认类型与Skill → 执行结构化 → 用户核对知识点 → 定向修正 → 明确确认后发布”。原有数据源、模型、知识库、图谱、Skill及历史治理成果保留。

## 使用入口与操作

进入 **运营治理 → 新闻公告语义治理**，页面地址：`http://127.0.0.1:5173/#/operations/documents`。

1. 搜索股票名称或代码，选择新闻、公告；支持本页全选和当前筛选范围跨页全选。也可切换“按股票批量”，选择多只股票及日期范围。总股票数、总篇数不再沿用20只／50篇上限，后台逐篇处理。
2. 点击生成治理方案。LLM读取可取得的完整正文，提出主要／次要类型、知识归属、推荐Skill、待确认事项。此阶段只生成方案，不发布知识。
3. 打开文档，填写审核人，修改类型、归属对象及Skill组合，点击“确认方案并进入执行”，随后点击“执行结构化治理”。如有能力缺口，可以创建专项Skill草稿、测试、审核启用后纳入方案。关闭或刷新页面不等于确认。
4. 查看中文知识卡片：知识点、涉及对象、时间、具体数值、影响方向、信息性质、原文引文及链接。普通项在点击批量确认时未标记不符合即视为符合；模型推断等重点项须逐项明确确认，或标记不符合并填写原因。
5. 点击提交修正，后台只重分析问题项，保留其他已确认内容与事实ID。支持多轮反馈；任务失败后点击“按原意见继续修正”。直到结果符合后点击“确认本批结果并发布”，或选择“本篇不治理”。最终报告和历轮历史保留。

展开“专业核验、原文与历史版本”可以查看完整原文、逐字段证据、模型与Skill溯源、版本差异及审核历程。治理记录可以查看任务阶段、文档级进度和失败原因。进度100%表示该轮已处理完，并不代表所有文档质量通过。

## 新增Agent与Skill

Agent：`DOCUMENT_SEMANTIC_GOVERNANCE_AGENT`，同时补充既有股票数据治理Agent可调用的专项Skill关联。

| Skill | 用途 |
| --- | --- |
| `DOCUMENT_SEMANTIC_ROUTER` | 全文识别、多类型、对象层级与治理方案 |
| `FINANCIAL_DISCLOSURE_GOVERNOR` | 业绩、计提、减值与财务指标 |
| `CAPITAL_OPERATION_GOVERNOR` | 定增、融资、回购、分红与发行 |
| `SHAREHOLDER_PERSONNEL_GOVERNOR` | 股东、控制权、持股与人事 |
| `JUDICIAL_RISK_GOVERNOR` | 诉讼、处罚、担保、质押及风险 |
| `CORPORATE_OPERATION_GOVERNOR` | 合同、中标、投资与经营事项 |
| `SUPPLY_CHAIN_RELATION_GOVERNOR` | 客户、供应商、产品与经营往来 |
| `POLICY_INDUSTRY_EVENT_GOVERNOR` | 政策、产业、原材料与板块背景 |
| `MARKET_OBSERVATION_GOVERNOR` | 个股、板块、榜单、量价与资金 |
| `RESEARCH_OPINION_GOVERNOR` | 预测、评级、媒体／专家观点 |
| `GENERIC_EVIDENCE_FACT_GOVERNOR` | 通用证据与无直接相关事实 |

现有 `NEWS_NOTICE_EVENT_GOVERNOR` 继续作为受控入库能力使用。专项Skill提供语义规则和输出契约，写库仍通过既有受控服务执行，不向LLM开放任意SQL。

模型自动生成的专项草稿不会自动启用；必须通过当前版本真实模型及证据契约测试并由用户审核。修改草稿指令或版本后旧测试不再有效，需要重新测试。测试不写正式事实，测试通过也不等于抽取完整性已达到生产标准。

## 质量规则与异常处理

| 场景 | 行为 |
| --- | --- |
| 缺正文、原文截断 | 标记缺失／部分完成，阻止作为全文成果发布 |
| 表格金额或百分比 | 校验原文单元格、列与表头单位，不把其他列数值冒充本指标 |
| 数值正负号 | 原文`-2.65亿元`保持负号；“同比下降2.48%”原始值保留`2.48`，下降含义保留在摘要和影响中 |
| 数值性质与期间 | 中文显示“预计”“约”“不超过”“不少于”与所属期间；`万分之五`显示原表达及`0.05%` |
| 公司／证券主体漏引 | 提供原文定位辅助，最多一次自动模型修复；仍需原文和对象证据门禁，不凭股票标签补关系 |
| 板块、市场或专家背景 | 按确认对象范围归属；不强行挂到目标公司 |
| 作者“套利”观点 | 保存为作者观点及归因，不当作监管裁决或已证实违法 |
| 模型推断／不确定项 | 突出重点确认；利润负向不自动等同股价必然下跌 |
| 网络失败、503、空输出 | 记录失败及真实备用模型调用；不生成伪事实。用户意见和上一轮成果保留，可重试 |
| 方案、原文或Skill变更 | 签名和版本冲突门禁，旧任务不覆盖新成果，须重新确认 |
| 用户修正 | 仅改指定事件／关系；保护未指出的知识、关系端点及事实ID，多轮不限 |
| 阅读与修正输出混用 | 阅读阶段不提供上一版结构化结果和补丁指令，只接受阅读契约；修正阶段只提供待修正项契约及只读上下文，不复制事实ID或标准化存储字段 |
| 用户选择不治理 | 停止此篇流程，保留原文与历史，未发布候选按受控审核处理 |

## 真实模型验收与范围

以国际实业 `CN_A:000159` 新闻8718《计提1.07亿元预计负债，业绩或由盈转亏》进行真实模型验收。复制原文和已配置模型至内存数据库，生产数据库只读，凭证不输出至验收文件。

第一次成功验收生成 **14个事件＋9条关系**，全部为待审核候选：包括计提1.07亿元、负向利润影响、税务争议与诉讼程序边界、负经营现金流、三次终止定增、江苏融能／新疆融能、认购资金构成与作者套利观点。结果位于 `real-model-verification.json`。此份验收覆盖真实规划与抽取，未代用户发布生产成果。

最终真实模型定向反馈闭环验收使用 `--verify-feedback-loop`，**通过**。生成 **13个事件＋7条关系，共20个候选知识点**，真实模型调用9次，均成功。7项关键语义检查和9项修正／发布检查全部通过；结果位于 `real-model-loop-verification.json`，历史版本2份。

在内存副本中模拟用户指出“请区分计提与实际支付”，LLM重读原文、仅修正计提事件，更新摘要为“该1.07亿元为会计计提的预计负债及预计利润减少金额，不代表公司已实际缴纳全部税款；实际补缴税款及滞纳金尚待后续发生”。修正事件保留事件key并建立新事实，其他已确认事件、关系及事实ID保持不变。明确确认后，内存副本的最终报告为 `PUBLISHED`，本批事实为 `ACCEPTED`；生产文档未被代为确认或发布。

验收检查计提1.07亿元、负经营现金流2.65亿元、负向利润影响、2.4亿元和4亿元借款上限、作者套利观点、诉讼程序边界、定向修正、已确认事实ID、历史和发布事务。各次结果分别保留时间戳文件；先前网络失败、主体证据不足、阅读返回补丁及模型试图重写非目标事件的失败也如实保留，未降低质量门禁。最后两类问题通过阶段契约隔离和受限修正上下文解决。不同轮次抽取项数有变化，验收以语义和证据检查判断，不以数量判断完整性。

再次执行数据保留检查通过：76张表、schema变化0、备份主键丢失0、外键违规0；在线健康检查及中文文档查询通过。

## 兼容与回滚

如需回滚，应从备份提交建立独立worktree核对文件，再逐项撤回本轮增量代码；Skill通过历史版本建立新的回滚修订。保留已经产生的原文、事实、报告和审核历史，无需删除新字段或旧表。不要重置当前工作区，也不要用备份数据库覆盖此后新增业务成果。
