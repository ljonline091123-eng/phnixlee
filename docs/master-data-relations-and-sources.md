# 主数据、基础数据、关系与数据源方案

- 日期：2026-09-20。
- 状态：设计稿；本轮核对代码及公开入口，不代表新数据源或领域模型已经接入。
- 衔接：[股票知识图谱架构草案](stock-knowledge-graph-architecture.md)。
- 覆盖：中国内地及香港证券、上市与未上市企业、股权控制、经济往来、司法信息；跨境其他司法辖区后续扩展。
- 交付边界：确定对象、逻辑表、来源、流程和验收；本轮不建业务表、不运行迁移、不批量抓取企业数据。

## 1. 建设目标与数据层次

由股票清单扩展为以主体身份为基础的数据底座。公司、自然人、机构、投资载体可以在没有证券代码时存在；股权、交易、合同和司法记录通过规范主体 ID 相连，再映射到股票。

| 数据层 | 内容 | 更新方式 |
| --- | --- | --- |
| 核心主数据 | 公司、主体、证券、上市记录、产品、项目、法院等的规范身份 | 永久内部 ID，别名和外部标识按历史维护 |
| 参考基础数据 | 地区、司法辖区、币种、单位、交易场所、行业体系、关系与程序枚举 | 具名体系及版本管理 |
| 时点与期间事实 | 工商属性、股权持仓、控制、财务、分类归属、交易余额、风险暴露 | 保存业务日期、可获知时间和系统版本 |
| 事件与业务过程 | 增资、股权转让、签约、履约、回款、起诉、裁判、执行等 | 追加事件及更正，连接相关对象和事实 |
| 来源与治理 | 原文版本、证据定位、来源断言、主体解析、冲突、审核、覆盖 | 全链路保留来源和形成方法 |

基础数据不等于静态数据。公司注册资本、注册地、法定代表人、存续状态和股权也会改变，不仅保留当前值。

## 2. 主数据对象和逻辑表

以下为逻辑设计，具体字段类型、索引与迁移待后续实现评审。

| 逻辑表 | 必要内容 | 主要约束 |
| --- | --- | --- |
| party | party_id、主体类型、规范名称、身份解析状态 | 公司、自然人、机构、基金载体分别识别；姓名或简称不作为唯一键 |
| company | company_id、party_id、注册司法辖区、法律形式 | party_id 与公司身份一一映射；未上市公司可存在 |
| company_profile_version | 登记状态、设立日期、注册资本及币种、登记地址、经营范围、法定代表人引用、有效与记录时间 | 注册资本、实缴资本、净资产分开；经营范围不直接证明实际开展业务 |
| party_identifier | 主体、标识体系、值、签发或登记辖区、有效期、证据 | 内地统一社会信用代码、历史注册号、香港公司注册编号/商业登记标识等分别存；不用跨辖区裸字符串合并 |
| party_name | 主体、法定名称/曾用名/简称/英文名、语言、有效期、来源 | 曾用名支持历史司法和合同匹配；保留原名与规范名 |
| security | security_id、issuer_company_id、工具及股份类别、权利定义 | A/H 通常为不同证券；发行公司共用一个规范主体 |
| listing | listing_id、security_id、交易场所、交易板、代码、币种、上市期间 | 代码有历史；新三板基础层/创新层属于带时间的挂牌属性，不能固化为永久身份 |
| share_capital_observation | 公司/股份类别、股本、库存股、投票权分母、基准日、口径、证据 | 为持股比例提供同口径分母，不混用某类别与公司总股本 |
| business_segment | 公司、分部、业务定义、报告期间、收入/利润等观测引用 | 分部口径随披露版本保存 |
| product / project | 产品、材料、项目的规范身份、规格或范围、别名 | 项目与实施公司分开；同名项目不自动合并 |
| organization / court | 非公司机构、法院或其他程序机构、辖区及编码映射 | 法院名称变更保留历史；仲裁机构与法院分别标识 |
| taxonomy / category | 分类体系、提供者、版本、编码、层级 | 行业、主题、指数与类型定义语义分开 |

Person、Organization、InvestmentVehicle 等使用 party 注册身份；载体有公司法律外壳时复用身份并附角色，不再重复生成公司。集团集合可作为 EntityGroup，但不能擅自取代合同签约或持股法律主体。

### 2.1 身份解析规则

1. 先按同辖区、同标识体系的登记标识匹配，再校验名称和有效期；不同来源标识冲突进入审核。
2. 证券代码先定位上市记录，再定位证券和发行主体；不得用代码直接充当 company_id。
3. 名称、地址、法定代表人等只用于辅助候选匹配，不用同名自动合并。司法文书或合同未给出足够身份时，保存未解析当事人。
4. 分公司、子公司、集团、实际控制人分别建身份和关系；分公司使用 party 的分支机构角色连接所属法人，不默认具有独立法人资格。法定代表人不自动等于股东或实际控制人。
5. 第一大供应商等匿名主体限定在披露公司、报告和期间范围，不凭上下文猜测实际公司。
6. 主体合并、拆分和误匹配撤销保留解析历史、审核人与映射版本；图投影引用规范 ID，不改变原始披露名称。

## 3. 股权与控制关系

沿用架构草案的 OwnershipFact、ControlFact 和计算型间接权益模型，逻辑表如下：

| 表或事实 | 字段重点 | 规则 |
| --- | --- | --- |
| ownership_fact | 持有人、被投资公司、可选股份类别、数量、比例及分母、登记/受益口径、持仓基准日、证据 | 直接持有、受益权益、名义安排分别记录，避免重复计算 |
| control_fact | 控制方、被控制公司、股权/协议/董事任免等依据、单独或共同控制、有效期 | 控制必须有依据，不仅看持股比例 |
| concert_arrangement | 参与方、协议、权利范围、有效期 | 一致行动不自动等于共同控制或实际控制 |
| derived_equity_exposure | 路径、输入版本、计算规则、间接经济权益、完整性 | 循环持股和多路径单独处理，不对任意路径求和 |
| ownership_event | 增减持、增资、回购注销、转让、并购等事件及阶段 | 未交割不确认为已经取得股权 |

从这些事实生成参股关联、控股关联、同一控制方、共同股东等股票关系。各类联系保留原因与路径；同一托管或名义账户不证明最终投资者相同。前十大股东披露不能视为完整股东名册。

## 4. 经济往来：约定、履约、资金与余额

经济往来应拆成可核对的业务事实，而非一条没有细节的合作边。

| 表或事实 | 表达内容 | 与其他事实的区别 |
| --- | --- | --- |
| contract | 合同身份、参与方角色、标的、数量、金额币种、税额口径、期限及生效条件 | 合同签订不是已确认收入 |
| contract_event | 意向、中标、签约、生效、变更、取消、完成 | 中标不是已签约，更不是已履约 |
| fulfillment_observation | 发货、交付、验收、服务进度 | 只有证据支持时记录，不从公告合同额推算 |
| settlement_observation | 开票、结算及应收应付，明确类型、期间或时点、对应合同/对手 | 开票不等于收入确认；应收不等于收款；汇总余额不伪拆交易明细 |
| payment_observation | 付款人、收款人、金额、币种、时间及授权凭证 | 主要依赖企业授权数据或明确公开披露，不能由应收反推现金流 |
| supply_chain_fact | 供应商、客户、产品、地区、期间、销售或采购额及占比 | 允许只有披露期汇总而没有合同明细；金额与占比分母明确 |
| loan_fact | 债权人、债务人、额度、余额、利率口径、期限、偿还事件 | 授信额度不等于实际借款余额 |
| guarantee_fact | 担保人、被担保义务、受益方、额度、实际责任余额、范围及解除 | 担保敞口不等于已经发生损失 |
| pledge_fact | 出质人、质权人、质押资产、数量、关联债务、生效及解除 | 质押不直接转移股权或控制权 |
| project_participation | 项目、投资人、运营方、份额、承诺与实缴、阶段 | 合资公司复用 Company 身份，项目独立 |

RelatedPartyTransaction 作为有标准和日期的交易分类关联到以上事实，不能只因同一主题或同一普通股东就认定关联交易。

公开渠道适合披露的重大合同、前五大客户供应商、关联交易、担保、借款与余额等，往往匿名、汇总或不完整。企业全部订单、发货、发票、银行流水及逐笔收付款一般需要企业授权 ERP/财务/合同等系统接入，商业工商接口也不当然拥有这些数据。

### 4.1 可得到的股票关系

股票 -> 发行公司 -> 对外投资、交易、合同、担保或借贷事实 -> 对手公司 -> 对手证券。若涉及子公司，经过当时有效的控制关系，并标记对子公司的关联暴露，不改写为母公司的直接交易或债务。

图中分别显示参股、客户供应商、共同项目、债权债务、担保等原因。关系金额、持股比例、收入占比保持各自意义，不混成没有定义的关联强度。

## 5. 司法信息：建议纳入基础模型并分期采集

司法信息包括诉讼及其程序、执行、破产等；仲裁作为另一个程序类别。行政处罚和交易所纪律处分分别建监管事件，不能混算为法院案件。新闻只提供待核对线索。

### 5.1 争议、程序、事件三层模型

| 表 | 内容 | 关键约束 |
| --- | --- | --- |
| legal_matter | 被证据支持的争议事项及业务关联，可选连接合同、借贷、担保等 | 并非所有程序都能安全归并，允许暂不确定争议归属 |
| legal_proceeding | 辖区、法院/机构、原始及规范案号、程序类型、审级、受理日期、当前已知状态 | 一审、二审、再审、执行各有记录，以明确依据关联，不覆盖前案 |
| proceeding_link | 上诉、再审、执行依据、合并/分离等程序关系 | 保存连接依据，不只按当事人相同合并案件 |
| case_party | 原告、被告、申请人、被申请人、被执行人等角色、原文姓名、主体解析结果和依据 | 每程序单独角色；允许 party_id 未解析，保留原文名称 |
| legal_event | 起诉披露、受理、保全、裁判、送达、生效确认、履行、执行、撤销等 | 状态有来源日期及证据；不从裁判日期自动推断已生效 |
| legal_amount_fact | 诉请、反诉、判决义务、和解、执行标的、已执行金额等类别与币种、日期，关联具体义务和责任主体 | 各类金额不可直接相加，也不能与财务预计负债混为同一数值；多被告保留责任份额或连带责任范围 |
| legal_document_link | 文书、裁定、公告、上市公司披露等版本及证据片段 | 同文书转载去重，不等于不同文书或程序均为重复 |
| enforcement_measure | 执行、限制消费、失信、冻结等措施，关联程序、对象及生效/解除 | 不同措施独立，撤销或解除保留历史，不永久贴标签 |

案件身份采用内部 proceeding_id，外部键以辖区、法院、规范案号及程序类别核对；案号缺失时只建来源记录和待解析候选，不强行造一个正式案号。破产程序另记录申请、受理、重整、和解、清算等阶段，申请不等于法院已经受理或企业已清算。

仲裁往往不公开，公开裁决或司法执行引用只能覆盖一部分；程序模型应支持它，但不承诺公开来源可获得完整仲裁记录。

### 5.2 风险解释与统计

- 被起诉不等于败诉，被执行不等于失信，原告涉诉也不能一律视为负面。
- 终结本次执行不等于执行完毕；案件结案不必然证明全部债务已经履行。
- 子公司涉诉连接到该子公司，股票侧展示控制路径与可能暴露，不说上市母公司直接被诉。
- 诉请金额不是确定损失；按净资产等指标计算重要性时，必须指明金额种类、主体口径、币种和时点，不把单一比例直接变成损失预测。
- 按争议数、程序数、文书数分别统计，避免一审、二审和执行重复累计为三起独立争议，无法确认同一争议时明确统计口径。
- 未检索到记录只表示指定来源、范围和时间内未发现；未公开、匿名化、访问限制和历史缺失均可能导致漏检，不能显示为没有诉讼。

先从上市公司关于重大诉讼、仲裁及进展的披露建立可验证样本，再以公开司法记录和授权商业数据补齐。同步预留合同及担保连接，才能解释某项司法风险与其他公司和股票的具体关系。

## 6. 数据源与获取方式

### 6.1 来源矩阵

以下是候选来源及用途，不代表各站提供免费、稳定、可批量使用的接口。字段权威性、授权、历史覆盖、延迟与样例质量必须按数据产品逐一验收。

| 数据 | 优先来源 | 补充来源/获取方式 | 覆盖边界 |
| --- | --- | --- | --- |
| 内地证券、上市和挂牌信息 | [上交所](https://www.sse.com.cn/)、[深交所](https://www.szse.cn/)、[北交所](https://www.bse.cn/)、[全国股转系统](https://www.neeq.com.cn/) | 已有 AkShare 及证券清单适配；按条件使用官方文件或授权接口 | 主体登记、股权穿透不是证券名单能力 |
| 香港证券与披露 | [HKEXnews](https://www.hkexnews.hk/index_c.htm) 的披露和相关官方证券资料 | 已有港股名单与公告适配；股份权益披露、CCASS 按各自范围评估 | CCASS 参与者/名义持有不能直接当受益股东 |
| 内地公司登记 | [国家企业信用信息公示系统](https://www.gsxt.gov.cn/index.html)及相关登记公示 | 官方许可查询/文件，或经授权的商业企业数据 | 非完整实时股东名册；公开查询可有访问限制，历史字段需单独核对 |
| 香港公司登记 | [香港公司注册处](https://www.cr.gov.hk/sc/home/index.htm)及其电子服务 | 按其查册和文件获取条件办理，部分资料可能付费 | 不假定存在开放免费批量接口，文件内容与权限逐项验证 |
| 法定公司披露、股权、子公司和控制 | [巨潮资讯](https://www.cninfo.com.cn/new/index)、交易所/股转披露、HKEXnews，发行人法定报告 | 年报、半年报、权益变动、招股、并购和关联交易等原文结构化 | 前十大/大股东不等于全部股东，发行人网站副本需核对版本和正式出处 |
| 行业、主题和类型输入 | 具名行业与指数编制方、交易所或正式分类文件 | 授权金融数据产品；已有来源只能作各自口径的输入 | 主题列表不同提供者定义不同；蓝筹、红筹不能用一个无说明来源定论 |
| 供应链、交易、合资和风险关系 | 定期报告附注、重大合同、关联交易、担保、借款和项目披露 | [中国政府采购网](https://www.ccgp.gov.cn/)的适用采购/中标/合同公告；授权商业结构化数据 | 采购公开信息仅覆盖适用范围；中标不证明已签约履约，客户供应商可能匿名 |
| 全量真实交易及资金往来 | 企业授权 ERP、合同、财务和结算系统 | 经授权的文件导入或系统接口 | 无法从普通公开工商、行情网站获得所有逐笔经营数据 |
| 裁判与程序披露 | [中国裁判文书网](https://wenshu.court.gov.cn/)、上市公司诉讼仲裁公告 | 正式法院文书、许可查询或授权司法数据 | 公开覆盖不完整，文书可能匿名、撤下或未公开，缺失不等于没有案件 |
| 法院公告 | [人民法院公告网](https://rmfygg.court.gov.cn/)及法院公开公告 | 送达等公告与已有程序交叉核对 | 公告不是判决结论，角色、程序与生效状态须另核对 |
| 执行及失信等措施 | [中国执行信息公开网](https://zxgk.court.gov.cn/) | 官方披露、解除或撤销记录及授权商业数据 | 被执行、失信、限制消费等类型分别记录，需更新有效状态 |
| 破产重整 | [全国企业破产重整案件信息网](https://pccz.court.gov.cn/)及发行人披露 | 正式裁定、管理人公告和相关程序文件 | 申请、受理、重整和清算阶段分别表达 |
| 香港司法程序 | [香港司法机构](https://www.judiciary.hk/)提供的公开判案及程序服务、HKEXnews 发行人公告 | 按对应服务的公开、付费和查询条件获取 | 内地接口不能替代香港覆盖；案件及程序标识采用辖区规则 |
| 行政处罚和监管处分 | [信用中国](https://www.creditchina.gov.cn/)、对应监管机构和交易所正式披露 | 许可查询与授权产品 | 与法院诉讼分开统计，更正、撤销和期限保留历史 |

商业候选可以评估企查查、天眼查等企业数据产品，以及 Wind、Choice、同花顺 iFinD 等金融数据产品。具体公司身份、历史股权、司法、批量调用及再展示权限以实际产品和合同为准，本轮没有验证或购买其 API，也没有将这些品牌视作已接入来源。

AkShare 是数据接入工具，不等同于原始信息发布者。每条记录同时保存配置来源、实际发布来源、传输适配器、原始 URL 与报告/接口版本；不能把经过新浪或东方财富的字段因为路由名为官方就改标为官方原始数据。

### 6.2 本轮公开入口核对结果

2026-09-20 使用无登录的只读 HTTP 请求做入口检查，没有提交企业/个人查询，没有下载案件清单或证明数据 API 可用：

| 入口 | 观察结果 | 可得出的结论 |
| --- | --- | --- |
| 巨潮、HKEXnews、香港公司注册处、上交所、深交所 | HTTP 200 HTML 响应 | 入口响应正常，正文获取和 API 能力仍须专项验证 |
| 裁判文书、执行信息、法院公告、破产重整、中国政府采购 | HTTP 200 HTML 响应 | 可定位官方入口，不代表无登录可批量查询或覆盖完整 |
| 国家企业信用信息公示系统 | HTTP 521 | 本环境本次未能完成普通请求；保留官方参考地位，自动接入待验证 |
| 信用中国 | HTTP 412 | 本环境普通请求受限，未继续自动采集 |
| 北交所、全国股转系统 | HTTP 200，但为短脚本/cookie 页 | 不能当作有效证券页面或数据接口成功 |
| 香港司法机构根入口 | HTTP 200，为前端跳转页；尝试的具体中文路径返回 404 | 根入口可定位，具体检索服务与路径需后续核对 |

技术受限的入口不降低其事实来源地位；自动采集能力与来源权威性分别评估。接入采用来源允许的 API、导出、文件或人工归档方式；本轮没有绕过访问控制或承诺免费全量抓取。

## 7. 采集、标准化与治理流程

```mermaid
flowchart LR
    S[授权接口、正式文件、人工导入] --> R[原始记录与文档版本]
    R --> N[字段标准化与证据定位]
    N --> I[主体注册与实体解析]
    I --> A[来源断言和业务事实候选]
    A --> V[口径、时间、冲突与审核]
    V --> F[规范主数据与事实版本]
    F --> G[股票关系视图和图投影]
```

原文存储与图重建隔离，保留原字段、内容哈希、原始单位、下载或导入时间、来源发布时间、许可证和使用范围。PDF/表格解析后的事实应定位页码、段落或单元格；扫描件的 OCR 结果保留提取质量，数字和身份有疑点时进入审核。

从证券清单建立发行公司，再优先扩展披露的控股子公司、主要股东、重要交易对手、担保方和司法当事人。按研究范围及关系重要性拓展，不一开始将所有企业无限穿透或交给模型全市场匹配。

不同来源说法并存，并按字段和事实类型选择规范视图。登记身份、证券身份、合同条款、司法状态各有适当权威来源；时间不同、币种不同或口径不同先分清，再判冲突。

### 7.1 来源能力登记

source_capability 至少保存：来源与原始发布者、数据集、司法辖区/市场、实体及字段范围、文档入口、许可获取方式、认证要求、费用/配额、历史起点、更新节奏、样例验证结果、健康状态、连接器版本。

状态分为 REGISTERED、ACCESS_VERIFIED、SAMPLE_VALIDATED、PRODUCTION_READY、DEGRADED、DISABLED。入口 HTTP 200 最多作为访问检查证据，不能越过样例解析、身份正确性及授权核查而标生产可用。

fetch_run 记录查询对象、来源及时间范围、实际查询时间、状态、返回数量、分页是否完整、错误与证据版本。区分 SUCCESS_EMPTY、ACCESS_RESTRICTED、FAILED、PARTIAL 等；失败不能落成零案件、零股东或没有交易。

## 8. 时间、更新与质量要求

所有重要事实遵循业务时间、可获知时间、系统记录时间。持仓基准日、报告期、合同生效日、案件受理日、裁判日与信息发布日各有语义。只有日期的来源保留时间精度，不伪造秒级时间。

建议更新节奏是任务目标，须受许可、配额与数据发布频率约束：

| 数据 | 建议触发 |
| --- | --- |
| 证券与上市安排 | 交易日名单核对，加上市/退市/转板事件触发 |
| 公司登记与名称 | 初始化完整核对，重点主体定期及变更触发；频率按可用授权确定 |
| 股权、控制与交易关系 | 披露事件增量更新，定期报告季核对；未披露时保留基准日与陈旧提示 |
| 合同、担保和诉讼 | 公告增量触发；活跃案件/重大合同按许可定期复核 |
| 执行措施与解除 | 重点主体按许可定期核对，明确本次查询覆盖和状态有效时间 |
| 财务观测 | 新报告或更正触发；历史不覆盖 |
| 行情 | 根据授权源与策略时效单独调度，不与公司主数据混用更新周期 |

最小质量要求：主体引用完整；来源身份不冒充原发布者；重要事实有证据或计算谱系；比例有分母；金额有币种与种类；历史有效时间不倒置；缺失与零值分开；案件角色和主体匹配有依据；来源重复与事实冲突分开处理。

股权比例校验只在相同时间、股份类别、权利口径及去重后的持有人集合内进行；不把不完整的前十大股东自动补齐到 100%。司法金额去重按金额种类、程序和义务范围处理，不将多份文书中的同一金额重复累加。

同一判决对多个主体承担连带责任时，公司个体责任暴露和集团或组合合计分别计算；聚合到同一义务时去重，不能按被告数量乘以判决金额。没有依据时不任意平均分摊。

覆盖分母使用预先确定的证券与公司范围，分别统计身份、股权、交易、司法来源检索与具体事实覆盖。司法字段记录已查询未发现、未查询、访问受限、匹配待核实等，不能共用一个无诉讼标签。

## 10. 建设顺序与决策

1. 建立逻辑契约：主体及登记标识、公司/证券/上市记录、股权、合同和司法程序字典；统一时间、证据、金额与角色。
2. 建立来源能力台账：按每类数据验证官方文件和已有适配器，登记访问、字段、历史、许可与费用；用样例决定是否采购商业结构化数据。
3. 做有限试点：例如选约 50 只覆盖 A/H/新三板的证券及其重要关联主体，包含同公司 A/H、匿名供应商、未上市子公司和已披露诉讼等情形。
4. 先建立身份、发行关系、登记快照、已披露股权控制，再补行业主题与类型；不等待所有全量穿透数据才能建立基础骨架。
5. 从正式披露抽取供应链、重大交易、担保及重大诉讼，形成带原文定位的样本；司法官网或商业源用于核对补充，不把未经核对新闻直接发布为事实。
6. 基于覆盖、准确率、原文可追溯性及成本决定扩源。需要全量股权历史、稳定案件更新时评估授权产品；需要真实经营流水时单独获得企业数据授权。
7. 再编排 Skill 和 Agent：硬规则负责身份约束、金额单位、时间与状态校验；模型负责有界文本提取和歧义候选；发布取决于事实审核和覆盖验收。

试点验收至少包括：跨市场同代码不合并、同公司 A/H 正确映射、同名当事人不误配、股东分母一致、托管不当控制、订单不当收入、担保不当损失、未交割不当持股、一二审不混号、执行不当失信、子公司涉诉不当母公司直接涉诉、访问失败不当零记录、重复文书不重复累计金额。

优先路线是复用现有证券与公告通道，先做官方披露可验证的主数据和关系；以覆盖缺口决定商业数据采购，企业授权数据作为独立扩展。此方案不承诺公开渠道能提供全量工商历史、全部实际经济往来或完整司法记录。
