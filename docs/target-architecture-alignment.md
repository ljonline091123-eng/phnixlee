# Gemini Quant Agent — 目标与架构对齐文档

## 2026-11-09 增量：独立 AI 证券分析师

新增“投研工作台 → AI证券分析师”，地址 `#/research/analyst`。用户选择股票、资料周期与真实模型，系统只读已有本地数据，生成带证据引用的整体逻辑及短、中、长期条件化趋势。独立页面、接口 `/api/v1/ai-stock-analyst` 和 `ai_stock_analysis` 历史记录与旧八维分析分离；不读取八维评分、不创建旧选股批次、不将模型推理升级为事实。

数据路径为“本地行情/财务/F10/新闻/公告/研究/问答/公司事实/知识文档 → 分类别的有界证据快照 → 真实 Model Hub + SENIOR_STOCK_TREND_ANALYST → 结构与引用核验 → 独立分析历史”。页面提供实际输入、原文链接、状态、计时、取消和历史查询。缺失数据、不可读正文与摘要取样须显式显示；分析成功不代表数据完整或趋势预测已被验证。

部署、备份、边界与验证见 [独立AI证券分析师说明](ai-stock-analyst-entry.md)。

> 对齐时间：2026-10-26
> 核心目标收敛：**以 LLM+Agent+Skill 驱动的“信号变化检测 → 刚性初筛 → 关联分析 → 结构化推荐 → 跟踪复盘 → 规则沉淀与自进化”量化投研飞轮。**

## 一、 核心业务目标与飞轮闭环

系统的唯一核心目标是**跑通自进化选股与投研闭环**：
1. **L0 变化检测**：对股票相关的多源信息（新闻、公告、行情、资金）进行实质性异动与语义事件提取。
2. **L1 刚性初筛**：通过确定性代码/SQL 将全市场快速压到候选池（<=50只）。
3. **L2 关联扩展**：结合知识图谱邻域、向量检索与产业链关系，自主组装“带证据链的全景包”。
4. **L3 语义研判与推荐**：由专职 Skill 与 LLM 基于锚定证据进行因果推理，输出带时间窗、入场价、置信度与证据 ID 的结构化预测。
5. **L4 跟踪复盘**：交易日收盘价跟踪，计算**基准相对超额（Alpha）与方向命中**。
6. **L5 沉淀与优化**：Meta-Agent 结合复盘归因与失败案例，结晶优化规则、参数与 Prompt，经门禁验证后晋级。

## 二、 L0–L3 落地详细设计

| 层次 | 职责划分 | 实现技术栈 | 核心纪律 |
|---|---|---|---|
| **L0 变化检测** | 过滤噪声，将长文本/行情流转为标准事件（如并购、放量、产能扩张）。 | 轻量 LLM (Flash 级别) + 定时任务/Webhook | **无实质变化不进漏斗**，降低下游算力与噪音。 |
| **L1 刚性初筛** | 确定性过滤基础流动性、市值、估值及技术形态指标。 | PostgreSQL / Pandas / SQL 规则引擎 | **100% 确定性**，严禁 LLM 介入数字计算。 |
| **L2 关联扩展** | 动态拉取行业、同业、上下游供应链及近期历史文本切片。 | 向量检索 (RAG) + 简化图谱邻域遍历 (Agent Tool-Calling) | **证据约束**，所有关联仅作为“待验证假设”。 |
| **L3 语义研判** | 综合证据链进行因果推导，吐出结构化可验证预测。 | Model Hub + 专职 Skill + Pydantic Schema 强校验 | **强地基约束**：严禁凭空编造价格或财报，必须绑定 `evidence_ids`。 |

## 三、 沉淀分类与晋级门禁体系

飞轮正向旋转的关键在于**沉淀物不能污染系统**。所有优化提案必须通过严格的门禁：

### 1. 沉淀分类
- **L0 变化规则/阈值**：新事件类型、敏感度参数。
- **L1 初筛参数**：候选池大小、动量/估值权重。
- **L2 检索/关联策略**：图谱权重、向量匹配阈值。
- **L3 语义 Skill Prompt**：推理 SOP、置信度扣减规则。

### 2. 晋级门禁（防过拟合四道关卡）
1. **基准相对（Benchmark-Relative）**：必须证明改进后对标所属行业指数/沪深300 的超额收益（Alpha）提升，而非单纯靠牛市 β。
2. **分层归因（Attribution）**：复盘时必须指明错误发生在 L0、L2 还是 L3，方可定向优化。
3. **样本量与显著性**：必须经历最小样本量（如 >= 30 个独立决策窗口）和留出集测试。
4. **人工审核 / 影子模式（Human-in-the-Loop）**：Meta-Agent 生成的优化方案默认落入 `SkillOptimizationDraft` 审核区，影子测试通过后由管理员或自动门禁批准上线，**绝不静默直接修改线上 Prompt**。

## 四、 模型选型标准（“前沿管推理，中档管量”）

模型不是成败的唯一胜负手，**评估与归因体系才是复利资产**。
- **Meta-Agent / 优化层**：选用顶尖推理模型（如 Gemini Pro / DeepSeek V4 Pro），负责复杂的失败归因与 Prompt 规则结晶。
- **L0 / L3 批量研判层**：选用性价比高、指令遵循与 Schema 输出极其稳定的中档模型（如 Flash 级别）。
- **选型硬指标**：结构化输出成功率（JSON 合规率）、**接地率（不幻觉价格/证据）**、因果推理得分、单位成本。通过 Model Hub 的 `/test` 与 A/B 路由动态选择。

## 六、混合评价与雷达图架构

选股评价采用“确定性评分 Skill + LLM 语义分析 + GraphRAG 证据 + 版本化权重 + T+3/T+5/T+7 复盘”的混合架构。LLM 不承担精确数值计算，也不能自动发布新权重。

| 评价维度 | 短周期权重 | 主要依据 | 计算方式 |
|---|---:|---|---|
| 基本面与盈利质量 | 12% | 收入、利润、现金流、资本回报 | 规则与模型融合 |
| 估值与盈利预期 | 6% | PE、PB、股息率、盈利预测 | 确定性规则 |
| 行业与板块景气 | 14% | 标准行业、同行收益、上涨广度 | 确定性规则 |
| 价格趋势与风险收益 | 20% | 区间收益、波动、回撤、量价 | 确定性规则 |
| 资金与交易行为 | 17% | 明确口径的资金字段、换手、成交 | 规则与模型融合 |
| 事件催化与信披可信度 | 17% | 新闻公告联动、兑现与冲突 | LLM 语义与引用校验 |
| 治理与股东稳定性 | 6% | 控制权、增减持、回购、解禁、质押 | 规则与模型融合 |
| 产业链与外部韧性 | 8% | 供应链、经营往来、司法和外部事件 | 规则与模型融合 |

长期综合研究方案作为草稿保留，未经样本外验证不进入生产排序。旧七维模型结果继续作为八维计算的证据输入，保持历史兼容。

评分遵循以下契约：

1. 八个维度均为“分数越高、当前证据下越有利”，雷达图展示原始维度分。
2. 权重只影响综合分，不改变雷达图形状；每个选股批次冻结方案、权重和 Skill 版本。
3. 缺失数据保持 `INSUFFICIENT`，不按 0 分、中性分或推测值填补。
4. 基础分只按达到覆盖率和置信门槛的维度归一计算；可信分向中性 50 分收缩：

   `trusted_score = 50 + (base_score - 50) * evidence_confidence`

5. 新闻与公告合并为“事件催化与信披可信度”；公司图谱是产业链、治理和外部风险的证据，不单列“图谱高分”。
6. “资金与交易行为”不把放量直接解释为主力或游资；只有口径明确的字段才能参与资金评分。

## 七、版本、评估与人工门禁

- 评价方案状态为 `DRAFT -> ENABLED -> RETIRED`，已发布版本不可直接编辑，只能复制新版本。
- 发布要求八维完整且权重合计为 100%；回滚是重新启用一个完整历史版本。
- 新批次在 `criteria_json.strategy_profile` 中冻结完整方案快照，历史候选不会被新权重静默重算。
- 历史候选可显式生成八维评分，原始证据、LLM 结论和人工决策不覆盖。
- 人工确认后的候选按真实后续交易日生成 T+3、T+5、T+7 收益、回撤与方向命中。
- LLM 只能提出权重优化建议，必须经过离线评估、样本外测试和人工发布。

## 八、功能入口与数据流

```text
数据源 -> Raw/Normalized/Serving -> 主数据/业务事实
       -> 知识文档/切片 -> 知识库/图谱/GraphRAG
       -> 硬规则候选 -> 七维语义证据 -> 八维评分
       -> 人工复选 -> T+3/T+5/T+7 跟踪 -> 评价方案新草稿
```

- `AI能力中心 -> 评价体系`：查看维度释义、复制版本、编辑权重与门槛、发布、停用、回滚和查看周期评估。
- `投研工作台 -> 选股与复选 -> 证据与复选`：查看可信综合分、八维雷达图及每维证据；旧候选可补算。
- 新建选股时选择已发布评价方案；选择结果随批次冻结。

本模块不实现自动交易，也不把评分解释为收益概率或买卖保证。

## 九、独立证券分析师的对话与证据跟踪

独立入口“AI证券分析师”直接基于已有资料形成整体研判，与旧八维评分保持分离。在此基础上增加“报告 → 用户对话 → 编辑确认 → 每日采集/比对 → AI复核 → 时间轴 → 继续对话”的持续研究流程。

- 原分析、用户确认的判断、每日复核分别版本化保存，不将用户确认或模型推理写成已验证的基础事实。
- 价位及量能由硬规则比对，新闻公告关键词提供线索；LLM结合证据和历史解释支持、挑战、未改变或无法验证，并提出修正判断。
- 每日任务复用持久化调度队列、注册数据源和已有采集落库能力。保留来源、时间、条件版本、报告版本、证据及模型/Skill调用；缺失和失败如实呈现。
- 新增只读Skill `STOCK_ANALYST_FOLLOWUP`，写入由受控业务服务执行，禁止任意SQL和模型直接写库。

接口、四张增量表、使用方法、监控时效及回滚说明见 [独立AI证券分析师](ai-stock-analyst-entry.md)。本能力用于持续证据验证，不等同于自动交易或已经完成未来行情准确率验收。
