## 修复原因与代码

原流程将任务持久化入队，但应用内没有自动消费该治理队列；启动按钮改变状态后也没有唤醒执行器。此外，实际 Skill 输入契约存在比页面更小的隐藏数量上限，新闻治理返回值缺少输出契约要求的 `failed` 字段。

- `backend/app/jobs/governance_runner.py`：应用内治理执行器、唤醒与状态查询。
- `backend/app/jobs/worker.py`：原子领取、唯一执行身份、长任务心跳续租、完成时校验领取者，兼容独立 worker。
- `backend/app/main.py`、`backend/app/core/config.py`：生命周期启停及 `GOVERNANCE_WORKER_ENABLED` 配置。
- `backend/app/api/document_governance.py`：全量身份选择、取消数量上限，筛选条件保持一致。
- `backend/app/api/stock_batch.py`、`backend/app/schemas/stock_batch.py`：提交与启动唤醒、进度字段、无限数量契约。
- `backend/app/services/document_event_governance.py`、`backend/app/services/document_semantics.py`：分批与逐篇回调、补取全文、输出契约修复、缺公司映射逐篇报告。
- `backend/app/services/stock_batch.py`：文档总量及分类统计、细分阶段持久化；相同百分比下阶段变化也保存。
- `backend/app/services/core_skill_defs.py`、`backend/skill_docs/NEWS_NOTICE_EVENT_GOVERNOR.SKILL.md`：去除治理相关 Skill 隐藏上限。
- `frontend/src/GovernanceProgress.tsx`：中文进度展示。
- `frontend/src/DocumentSemanticWorkbench.tsx`、`frontend/src/GovernanceRecords.tsx`、`frontend/src/batchGovernanceApi.ts`：全选、自动刷新、操作反馈及报告进度。
- `frontend/src/App.tsx`、`frontend/src/BatchStockGovernanceDialog.tsx`：取消主数据批量选择与提交的股票总量上限。

旧新闻检索记录会识别为摘要并补取登记来源全文，原 `content` 保留，全文与来源元数据增量存储。东方财富正文的合法站内跳转现在逐跳校验并跟随；来源、最终地址、跳转链、哈希与时间均保留。

## 手工验收

1. 刷新系统，进入“运营治理 → 新闻公告语义治理”，搜索精智达或其他股票。
2. 点击“全选本页”，再点“全选当前筛选范围”，核对已选数包含其他分页。
3. 点击分析选中文档，确认任务自动从等待进入执行，进度显示当前文档及模型阶段。
4. 或切换“按股票批量”，输入多只股票，保持“全部未完成文档（不限篇数）”，预览后创建并执行。
5. 在“治理记录”查看报告，核对已处理总量、成功、失败与部分完成数量；对于排队任务可以点击“立即执行”。
6. 对失败项查看具体原因及历史记录，确认没有将处理结束误认为质量通过。
