## 问题、原因与修复

| 用户问题 | 已核实原因 | 本轮处理 |
| --- | --- | --- |
| 财务、量价、资金等板块都显示新闻公告 | 本股总证据白名单不能证明引用属于该板块；旧结果混用了同一新闻 ID | 按来源表、事实类型和图谱关系分别建立七类证据卡；不再用新闻填充财务、量价或资金板块 |
| 多条资料缺少获取时间、列表过长 | 旧界面直接铺开模型引用，未提供统一排序和折叠 | 展示真实获取时间，倒序排列，默认五条，其余展开；未记录时间明确标注，不用发布时间冒充采集时间 |
| 没有逐条评分和加权板块分 | 旧模型只返回板块方向，无法追溯到每条数据 | 新分析契约要求每条引用提供影响方向、正负分和理由；服务计算板块平均影响分与加权贡献 |
| 补齐按钮看起来无效 | 弹窗遮挡反馈、详情未刷新，网络请求前尚未记录运行状态；F10 总成功被误判为资金流成功 | 弹窗内显示提交、错误、排队、运行和进度，防止重复提交；采集前持久化当前工作，完成后刷新详情；无有效资金流仍保留缺口 |
| 没结论、没雷达却统计成待复核 | 旧统计以模型调用 SUCCESS 为准，没有检查结论和评分完整性 | worker、批次 API、详情、评分读取接口和确认跟踪共用结论发布判定；失败不能计为待复核 |

分类规则：新闻只引用 `stock_news`，公告只引用 `stock_notice`；财务使用财务文档或财务观测；量价使用行情或市场观测；资金使用资金流观测；经营与股东使用公司/股东资料与相应事实；图谱使用本次输入的图谱关系。F10 财务和资金分区不能充当公司股东资料。关联股票资料仅用于有证据的跨股票联动，不能填入当前股票的资料卡。

财务、行情、股东等卡片同时展示能从原证据读取的具体数值及中文单位。只有标题、元数据、未注明来源类型的切片不提升为有效业务证据。

## 逐条评分、权重和雷达

新建分析和重试采用 `MULTI_SOURCE_SCORED_V4`。沿用原 JSON 存储，不另建事实表。

每条 `evidence_assessments` 包含：

| 字段 | 含义 |
| --- | --- |
| `reference_type` | DOCUMENT、FACT 或 RELATION |
| `reference_id` | 对应本次输入的真实文档、事实或关系 ID |
| `direction` | POSITIVE、NEGATIVE、NEUTRAL、MIXED 或 UNKNOWN |
| `score` | -100 至 100 的影响分：利好严格为正，利空严格为负，中性/交织为 0，未知为 null |
| `rationale` | 该条数据的具体作用和评分理由 |

类型不符、越界、重复、漏评以及正负方向不一致均不通过验证。未知不会被补为零分；未完成全部条目评分时不生成该板块综合分。

```text
板块原始影响分 = 去重后的逐条影响分之和 / 已完整评分的条目数
板块综合分 = 板块原始影响分 × 板块权重 / 100
```

例如两条新闻分别 +60、-20，原始分为 +20；板块权重 6.25% 时综合分为 +1.25。使用平均值避免仅因文档数量多而放大板块分。显示位置在板块右上角方向标签之后，同时列出权重和已评分条数。

现有八维评价方案保持版本与权重。七类资料卡从同一已发布方案映射权重，总额保持 100%，不另造一套叠加权重：

| 资料板块 | 对应现有评价维度权重 |
| --- | --- |
| 新闻事件 | 事件催化与信披可信度的 1/2 |
| 公告披露 | 事件催化与信披可信度的 1/2 |
| 财务业绩 | 基本面质量 + 估值与盈利预期 |
| 量价趋势 | 价格趋势与风险收益 |
| 资金进出 | 资金与交易行为 |
| 经营与股东 | 治理与股东稳定性 |
| 公司关联与图谱 | 产业链与外部韧性 + 行业与板块景气 |

七类资料卡的有符号影响贡献与原有八维雷达的 0—100 因子评分含义不同，不将两者混作同一总分。页面提供对应关系说明。雷达的缺失维度留空；结论未通过时不显示有效雷达。旧结果未逐条评分则显示“未评分”，不会从板块方向反推伪造条目分数。

## 统一结论发布规则

| 发布状态 | 页面含义 | 是否计有效/待复核 | 能否确认跟踪 |
| --- | --- | --- | --- |
| DATA_INSUFFICIENT | 数据不足，未分析 | 否，计数据不足 | 否 |
| MODEL_FAILED | 模型调用或返回校验失败 | 否，计失败 | 否 |
| CONCLUSION_FAILED | 有返回，但引用、置信度或结论完整性不合格 | 否，计失败 | 否 |
| SCORE_FAILED | 结论通过，但综合评分或雷达数据不完整 | 否，计失败；可补算评分 | 否 |
| READY_REVIEW | 有效结论和评分已生成 | 是，等待人工复核 | 是，仍需人工确认 |
| NOT_ANALYZED | 尚未分析 | 否 | 否 |

评分发布检查包括：可信综合分为有限数字且在 0—100、八个维度代码准确且不重复、权重合法且总和为 100、存在的维度分数合法。GET 评分接口同样受门禁控制，不能通过旧接口读取无效结论的陈旧雷达。

只读复核真实第 39 批：精智达、华宇软件、景嘉微、东方电子均为结论校验失败；汇总为 **有效 0、待复核 0、失败 4、数据不足 0**。原因是这批历史返回本身引用/结论校验不完整，不能因存在摘要而算通过。原始数据库记录保留；重新分析前不会伪造有效结论。

3. 浏览器检查无 JavaScript 错误、无 API 失败。真实历史第 39 批状态正确；明确标记的合成样本验证七类资料、具体数值、正负分、公式、5→7→5 折叠、有效雷达及 1280/1440 宽度无溢出。合成样本不是实际选股结论。

## 用户复验入口

1. 刷新“选股工作台”，查看第 39 批：四股应显示结论校验失败，不再计待复核；打开详情不应出现有效结论、雷达或可用跟踪按钮。
2. 对缺失板块点击“补齐数据”：弹窗内立即有提交/排队反馈，运行后能看到当前股票、板块和进度。来源返回空数据或错误时保留缺口和原因，不当作补齐成功。
3. 使用可正常完成复杂分析的模型新建分析，或重试旧结果。新结果应按七类来源展示数据，每条均有真实获取时间（或明确未记录）、评价方向、影响分和理由；超过五条可展开/收起。
4. 用条目分数均值乘以板块权重复算右上角综合分；缺项不得显示伪造的零分。检查雷达和批次状态是否与本股发布状态一致。
5. 历史没有逐条评分的结果需要重新分析；修复界面不会追填历史模型从未输出过的分数。

## 兼容性和回退

所有改动增量复用现有字段和服务；重新分析前保留 BEFORE_REANALYSIS 快照。查询历史仅在响应中纠正显示，不更改原审计记录。隔离测试与生产数据库互不覆盖。

如需回退，先另外保存当前修改，再从上述备份分支选择性恢复本轮涉及文件；不要重置整个工作区或用旧数据库直接覆盖正在运行的数据库。本轮没有结构迁移，因此代码回退不要求删表。数据库备份用于需要时的独立恢复核验。
