## 已实现

| 能力 | 实现与边界 |
| --- | --- |
| 主体主数据 | 公司、自然人、机构、项目、行业、板块主题、类型标签、产品和材料；UUID 标识，登记标识按辖区与体系唯一，不按名称自动合并 |
| 公司与股票连接 | 独立 Company / Security / Listing，引用现有 `stock_symbol.id`；创建映射必须提供证据，不修改旧股票记录 |
| 关系与事项 | 直接持股、控制、供应、合作、担保、借贷、竞争、行业、板块、类型、合同及司法事项；按类型校验属性与合法端点 |
| 独立证据 | 来源记录、内容哈希、不可覆盖的版本；相同内容幂等，更正追加；保存原文空白，旧图重建不删除已归档证据 |
| 人工审核 | 新事实均为 `PENDING`；接受或拒绝时记录审核依据、记录人及原状态；并发状态冲突返回 409 |
| 时间查询 | 有效期为左闭右开日期区间；`known_at` 约束系统记录、证据可获知时间和当时审核状态 |
| 股票兼容查询 | `stock-context` 返回公司映射、当前有效的已接受事实及缺失提示，最多 50 条并返回总数 |
| 旧证据归档 | 单篇同步导入；批量归档复用现有数据库任务队列与 Worker，1 至 100 个文档编号，校验入队时内容指纹 |
| 数据迁移 | 独立 Alembic 历史仅管理七张新表；显式目标、只读检查、结构漂移阻断，不接管旧表 |
| 前端工作台 | 数据中台新增“主体与关系”：主体主数据、证据资料、关系与事项、司法事项；创建、检索、分页、映射和审核闭环 |

持股必须说明比例分母或数量单位，控制关系必须说明控制依据。司法事项保留主体角色、程序、案号、法院及状态；金额区分诉请、裁判、执行、和解与预计负债，不将被诉解释为败诉或违法。

## 主要入口

基础路径：`/api/v1/foundation`。当前为本机单用户功能，不提供新的身份认证或租户隔离。

| 路径 | 用途 |
| --- | --- |
| `GET /status`、`GET /catalog` | 开关、计数、枚举、事实属性契约 |
| `GET/POST /entities`、`GET /entities/{id}` | 主体建档、检索和证券列表 |
| `GET /stock-options`、`POST /security-mappings` | 检索现有股票、关联发行主体 |
| `GET/POST /evidence`、`GET /evidence/{id}` | 证据版本及原文 |
| `POST /evidence/import-legacy` | 按旧知识文档编号归档 |
| `POST /evidence/archive-jobs`、`GET /evidence/archive-jobs/{id}` | 批量归档入队及进度 |
| `GET/POST /facts`、`GET /facts/{id}` | 事实录入、检索、证据和审核历史 |
| `POST /facts/{id}/review` | 带 `expected_status` 的审核 |
| `GET /stock-context?market=CN_A&symbol=...` | 新底座到旧股票界面的兼容查询 |

`GET /facts` 默认只返回已接受事实；不指定 `as_of` 时包含其全部业务有效期。治理工作台主动请求全部审核状态。审核状态仅支持待审核到接受或拒绝、已接受到拒绝；已拒绝记录不可改回，纠错需新增候选并保留原记录。

## 开关与运行

后端增加 `DATA_FOUNDATION_ENABLED`，默认 `true`；设为 `false` 后新业务接口返回 503，状态接口返回停用，前端展示停用状态。旧 API 不受该开关影响。开关不卸载 ORM，也不阻止旧启动流程的 `create_all` 建立空的新表；不能把它当成迁移回退或数据删除。

先安装 `backend/requirements.txt` 和前端锁定依赖，再遵循 [迁移说明](data-foundation-migration.md) 在数据库副本上完成 `preview -> check -> apply -> check`。真实库上线前应另行备份数据库并安排停写窗口。本次未执行该真实库操作。

正常 API 和前端启动命令沿用项目 README。批量归档只入队，需要已有独立 Worker 执行：

```powershell
# 在 backend 目录，显式指向与 API 相同的、已确认的目标数据库。
python -m app.jobs.worker
```

Worker 会处理该数据库中的其他待执行任务，不能为了试验归档而直接连接业务队列。归档不自动全量扫描、不重建旧图、不创建事实、不自动接受候选；如果源文档已变化，任务失败并要求重新提交。

## 本期不宣称完成的能力

- 尚未接入新的工商、股权穿透、供应链或法院外部数据服务；现有数据源保持原样。商业接口授权、调用预算和来源选择仍需确认。
- 尚未自动创建治理 Skill 或 Agent，现有模型不自动抽取并接受新事实。已提供受校验的 API、证据和任务边界供后续接入。
- 行业、板块及类型事实目前挂公司；证券与上市记录级大小盘、流动性、红筹等规则计算及历史分类尚未实现，不能用公司标签代替证券分类。
- 当前每个旧股票记录单独创建 Security / Listing，支持多个证券关联同一公司；暂不支持映射纠错、代码复用、历史发行主体变更及同一证券跨场所合并。
- 供应关系中的产品目前为文本属性，未连接产品或材料节点；没有产业环节图或板块上下游聚合。
- 司法记录是单主体程序观测，尚无跨程序案件归并、诉讼参与方消歧、金额去重和损失估算；借贷与担保亦不是完整多方债务模型。
- 证据存在和属性通过校验，不等于原文已被自动验证为支持该事实；记录人文本也不是经过认证的用户身份。禁止直接暴露到公网或作为多用户审批系统。
- `known_at` 重放本系统当时已录入且审核的信息，不等于历史市场的全量信息集。旧文档归档采用保守的本次收录时间，不猜测其原始公开时间。
- 未提供完整实体别名、冲突案件、事实替代链、规则版本、覆盖验收、图谱发布或增量投影。本次也没有切换研报及选股的读取路径，未引入 Neo4j 或重建旧图。

后续应先补证券级分类与身份历史，再按已确认授权接入来源及受控抽取，最后构建版本化图投影。各阶段继续保持旧工作流可用，不以重构名义覆盖既有成果。

## 验证

后端测试显式设置 `DATABASE_URL=sqlite:///:memory:`，测试自身使用隔离会话，不使用业务库。迁移测试使用临时 SQLite 文件；PostgreSQL 仅验证离线 SQL，未做真实实例验证。

```powershell
$env:DATABASE_URL = 'sqlite:///:memory:'
$env:PYTHONDONTWRITEBYTECODE = '1'
python -m pytest -q -p no:cacheprovider
```

最终结果：完整后端回归 **142 项测试及 2 项子测试通过**；前端 `npm run build` 通过。`git diff --check` 通过。两处既有行情测试仅修正了数据库会话隔离与固定时钟，没有修改行情业务逻辑。

浏览器验收使用本机临时演示数据库，不调用新外部数据源。通过主体创建、原文空白与双版本证据、证券映射、候选默认隔离、人工接受与撤销、审核历史、司法候选、股票上下文、主体关联跳转、分页、搜索、接口错误恢复和停用状态检查。1440、390、360 像素宽度均无页面横向溢出，已截图核对桌面及窄屏弹窗，未出现浏览器脚本异常。
