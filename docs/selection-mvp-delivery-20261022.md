# 选股分析 MVP 交付与验收记录（2026-10-22）

本轮围绕“选择股票与知识范围 → 生成候选 → 后台模型分析 → 查阅结论与依据 → 失败项重试 → 人工复核”完成增量修复。已通过真实模型20股验证、接口测试和浏览器验证。验收通过指链路、引用与数据保留通过，不代表未来收益或全部原始数据正确性已经验证。

## 一、如何查看本轮成果

1. 打开 <http://127.0.0.1:5173/#/research/selection>，进入“选股分析工作台”。
2. 在“历史分析批次”选择“第14轮”。页面应显示20只股票、208篇文档、20/20通过引用校验、0失败、0待核对。
3. 点击任一股票“分析与证据”，分别查看“分析结论、数据事实、原文与引用、关系与血缘”。新闻公告分析包含事件、影响方向、传导机制、时间与原句引用；缺失分项显示“证据不足”。
4. 点击“新建选股”，搜索中文名称、代码或字母；勾选“全选当前搜索结果”可全选，取消一只时呈半选状态。选择知识库和图谱后，查看本次股票覆盖与实际资料数量，再生成候选池。
5. 可切换第13轮查看原20股失败原因及重试入口；历史失败批次保留。第15轮为浏览器实际提交的单股规则流程验收任务，不是第14轮的20股模型结果。

界面默认加载最新批次，因此查看20股成果时请主动选择第14轮。

## 三、根因与处理

- DeepSeek的逐股恢复与契约重试调用未沿用选股任务的禁思考配置，出现令牌耗尽但正文为空。已统一禁思考与JSON输出参数。
- 模型曾出现跨股引用、将新闻当公告、改写或拼接原句。现按每股实际送入模型的资料提供引用白名单与错误反馈，检查来源类型、原句和关系编号。
- 引用待核对的分析不得确认入选；综合结论、目标价和置信度会撤销，需重新分析通过。拒绝入选仍可操作。
- 原备用Gemini模型被供应商返回404，本轮真实验证使用现有DeepSeek实例；没有擅自替换全局模型配置。
- 图谱归属关系只能证明资料关联，提示模型不得由此直接推出因果或资金动作。

### 数据缺口与边界

- 19只股票的资金流分项证据不足，1只股票（000007）的新闻分项证据不足，已标记为`INSUFFICIENT`，方向为`UNKNOWN`。
- 本批20只股票的行情基准均为`2026-10-15`，页面逐股显示，不是10月22日实时行情。本轮证明已入库数据可用于多源分析，没有将历史行情改写为最新行情。
- 模型未给出有充分依据的目标价，本批目标价为空。用户确认入选需自行复核并填写所需参数；本轮未代用户确认投资决策。
- 供应商故障仍可能发生。系统保留逐股错误、调用记录与重试进度，故障时不以本地规则盘点冒充模型分析成功。
- 引用校验不等同于原始资料权威性、数值全部正确、投资判断正确或收益验证。当前可交付范围为使用已入库数据的分析MVP；资金流补齐、行情刷新和收益评估仍需分别推进。
