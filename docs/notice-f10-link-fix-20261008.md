# 个股公告与 F10 财报关联修复验收

验收日期：2026-10-08。示例：港股黑芝麻智能（HK / 02533），A 股万科 A（CN_A / 000002）。

## 数据关系

正式财报属于个股公告。公告原始文件存入现有 `stock_notice`，F10“财报”以该表为依据生成分类视图，通过 `notice_id` 引用同一公告及原文。

财务指标仍使用现有 `stock_financial_report` 和 F10 财务指标缓存。指标期间不等于独立财报文件；未找到对应公告时显示缺口，不以指标记录伪造“已披露报告”。

同一期的完整报告与业绩公告分别保留。报告期与公告日期分别展示。报告年份不能可靠确定时显示“待核验”。ESG、致股东信函等历史文件保留在公告及“其他历史披露”中，不计入正式财报数量。

## 根因和修复

1. 港交所披露易查询日期要求 `YYYYMMDD`。原采集传入 `YYYY-MM-DD`，上游未明显报错，却返回不完整的旧范围。统一日期转换，并核验分页；达到分页上限且仍未取全时明确报错。
2. 原公告分类规则主要匹配简体中文，无法识别港交所繁体标题及原始细分类。现保留原始分类，同时计算统一中文展示类别，优先识别风险、担保、回购、投资及财务信息。
3. 原 F10 财报与公告分开采集，并将财务指标期间混入文件列表。现采集到披露文件后先通过受控公告服务入库，再生成 F10 投影；本地读取不触发远程采集。
4. 原港股同一期文件可能被合并成一份。现同时保留完整报告与业绩公告。
5. 巨潮资讯链接查询参数顺序不一致，曾造成证据对照误报。URL 比较现排序查询参数，数据库原始 URL 保持原样。

## 回填与回滚

在 `backend` 目录运行：

```powershell
python scripts/backfill_notice_report_links.py --market HK --symbol 02533
```

默认只预览，不联网、不写入。已完成备份且确需增量关联时增加 `--apply`；不带市场/代码条件可处理全部现有财报缓存。

回滚应仅撤回本次相对备份分支的代码差异，保留其他未提交成果。公告为增量补充的数据，不必删除；F10 缓存可从保留的公告重新生成。若确需恢复某个旧缓存，应先备份最新数据库，再按股票及缓存主键恢复指定记录。不要直接用旧数据库覆盖当前数据库，以免丢失随后采集的成果。
