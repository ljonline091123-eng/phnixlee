## 一、如何在页面验证

打开 `http://127.0.0.1:5173/#/operations/records`，或从“运营治理 → 治理记录”进入。

1. 搜索 `000159`，打开任务 **#533** 的“查看报告与成果”。
2. 在“阶段成果明细”展开“新闻公告结构化事件”。点击已分析新闻或公告对应的“查看数据与证据”。
3. 页面会自动定位成果详情。展开“结构化事实字段”和“原文证据”，核对事件类型、摘要、原文引用、正文覆盖范围、来源记录、正文哈希、模型调用编号及 Skill 版本。候选状态明确显示，不能视为已验证结论。
4. 业务数据、湖仓发布、文档切片和图谱检查项也可点击。明细及预览均支持分页；无数据时显示缺口，不显示虚构成果。
5. 点击“继续治理”，查看定向计划，再点击“执行定向续作并保留旧报告”。此操作实际创建新任务，页面切换到新报告并轮询执行状态。成功业务类型不重复采集，结构化只补当前正文及 Skill 版本未通过的文档。
6. 点击“生成并审核 Skill 优化”，查看失败原因、优化建议、基础版本 SOP 与建议 SOP。点击“执行离线检查”，通过后可以“批准并启用新版本”或“驳回草稿”。批准会实际发布新版本并保留版本记录；仍需下一轮治理验证效果。
7. 在“治理历程与报告版本”切换 #528—#533，查看各轮独立报告。续作不覆盖旧报告。

运行中的任务不能重复续作或生成优化草稿。过期基础版本的草稿不能批准，需要重新生成当前版本草稿。

## 二、结构化治理如何执行与存储

新增应用内 Skill：`NEWS_NOTICE_EVENT_GOVERNOR`（新闻公告结构化事件治理），已接入股票治理智能体的受控 Skill 执行链。不是仅保存新闻标题或文档切片。

执行顺序：证券—公司身份解析 → 查询本股范围文档 → 缺正文时补原文 → 真实模型抽取 → 原文引用门禁 → 写入候选事实与证据 → 更新阶段报告 → 按依赖发布湖仓、文档切片与图谱范围版本。

| 内容 | 保存位置与规则 |
| --- | --- |
| 新闻、公告原记录及正文获取状态 | 复用 `stock_news`、`stock_notice`；结构化状态及历史保存在原记录 JSON 中 |
| 原文证据 | 复用 `FoundationEvidence`，保存来源、URL、披露时间、正文及哈希 |
| 结构化事件 | 复用 `FoundationFact`，类型为 `NEWS_EVENT` 或 `NOTICE_EVENT` |
| 审核状态 | 事件只写为 `PENDING / CANDIDATE`，不自动升级为已验证事实 |
| 执行来源 | 保留公司主体、批次、流水线、智能体/Skill 执行编号、Skill/模型版本及模型调用编号 |
| 幂等与版本 | 同文档、同正文哈希、同 Skill 版本幂等；正文或版本变化保留历史并重新核验 |

模型引用必须能定位到实际分析原文。PDF 引用定位仅允许忽略排版空白，保存原文中的连续引用，不允许改动数字、文字或标点。引用不匹配时拒绝写入事实。

新闻检索摘要必须补正文，不能当作全文。已支持东方财富财经原文页面，以及巨潮资讯、港交所允许主机的官方公告 PDF；其他来源无法读取、扫描件需要 OCR、正文截断等情况明确标记缺口。

单轮最多处理 20 份文档；每批模型最多 5 份、每份最多 7000 字。新闻补正文最多 8 篇，公告 PDF 下载最多 4 份。额度耗尽明确标记待下一轮续作；长文摘录标记 `PARTIAL_BODY`，不计作全文完成。

当前 Skill 版本为 **1.0.4**。任务 #533 执行的是 **1.0.3**，其报告冻结保存；下一轮会按当时的当前版本重新核验，不能把历史完成数量直接当成新版本完成数量。
